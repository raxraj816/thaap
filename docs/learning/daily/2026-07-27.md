## 2. Payment Processing Concepts Learned

- A dispute outcome is operational evidence, not permission to rewrite the capture, chargeback allocation, refund, or ledger. Money truth remains append-only and separate.
- A caller-supplied network date is not authoritative policy. THAAP derives the response deadline from the immutable reason catalogue and received timestamp.
- A webhook retry is transport work over an already committed event. Manual redelivery must advance operational generation while preserving the exact event bytes and never re-enter payment or fraud orchestration.

## 3. Fraud Detection Concepts Learned

- Evidence versioning preserves what an analyst knew and exactly which version a manager submitted; that lineage makes later win/loss analysis trustworthy.
- Simulator `WON`/`LOST` outcomes are explicitly attested synthetic labels and cannot masquerade as card-network settlement truth.
- Webhook delivery success or failure is merchant-integration evidence, not a new fraud label or permission to change the originating decision.

## 4. Security Concepts Learned

- Evidence accepts closed booleans and inherited verification results only—no PAN, CVV, credentials, free text, or document upload surface.
- Tenant-qualified foreign keys, actor-derived merchant scope, role separation, exact idempotency, and append-only PostgreSQL triggers protect the workflow.
- Endpoint ownership verification stores only a random token digest, signs the challenge, compares the final response proof in constant time, and fences URL/secret-generation/expiry races.

## 5. Architecture / Design Notes

- `dispute_workflows` is a mutable, versioned projection; evidence, outcomes, and lifecycle events are immutable history.
- Every privileged dispute mutation locks and revalidates the live operator and
  credential first, then locks the workflow. Submission binds
  `submitted_evidence_version_id`, so later revisions cannot change the
  historical packet.
- Deadline semantics are intentionally closed at the boundary: API work is allowed at `now == dueAt`; expiry begins only at `now > dueAt`.
- Webhook challenge preparation and finalization are short database transactions around external HTTP. Endpoint-before-delivery locking and generation fencing prevent disable, rotation, worker, and redelivery races from creating sendable false state.
