## What The Later Hostile Pass Found

Three findings escaped earlier review and are recorded immutably.

- `ER-0096` (P1): the SDK regeneration gate had never been executed. Its first
  run failed, revealing a client generated from a contract predating the Chapter
  53-56 endpoints, which accepted a scenario runner token and never sent it. The
  consequence was silent: sandbox payments would have been recorded as live
  merchant traffic and entered live-only fraud metrics.
- `ER-0097` (P1): safe exceptions still reached the raw response body, request
  headers and full URL through `__context__`. `raise ... from None` clears
  `__cause__` and suppresses the printed traceback but does not delete the chain,
  and every existing assertion read only the rendered message.
- `ER-0098` (P1): `openapi-contract-check.sh` was never wired into the readiness
  gate and was red. All six scenario operations reject a merchant key presented
  alone, while the contract published `merchantApi` only.

## The Lesson Worth Carrying Forward

Two of the three shared one root cause: a gate that existed, had been reviewed,
and had never been executed. A matrix row that says "asserted by the script but
not yet demonstrated by a recorded run" reads as nearly done and is frequently a
red build nobody has looked at.

The correction is mechanical rather than cultural. Both OpenAPI gates are now
invoked by `scripts/commit-readiness-check.sh`, and
`scripts/commit_readiness_check_tests.py` fails if either is removed. No matrix
row whose proof is a script may close without a recorded run in its dossier.
