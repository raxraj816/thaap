## Engineering Lessons

- Database dialect proof matters: H2 accepted both a reserved PostgreSQL alias and an invalid outer-join lock shape.
- Operational workflow state must remain separate from payment ledger and fraud-label truth.
- Privacy-safe exception logging deliberately omits database exception messages and stack contents that can echo row data.
- Cooperative scenario execution does not require a second payment path: the browser/client calls ordinary public APIs while PostgreSQL owns lease, epoch, checkpoint, and immutable evidence truth.
- A report digest is meaningful only when a test recomputes it from exact canonical persisted bytes; checking that it merely exists is weak proof.
- Optional query filters need production-dialect proof: PostgreSQL requires typed null parameters, so explicit presence flags are safer than standalone JPQL null probes.
- Public demos must be rebuilt from documented runtime configuration. Chapter 43 found and resolved `ER-0058` without weakening the governed activation default: the fast one-row demo explicitly uses local-only `1`/`0`, while shared/default operation remains 100 eligible rows and 50% label coverage.
- A transactional outbox closes the database/Kafka dual-write gap but cannot
  create exactly-once delivery. Stable event identity plus an inbox committed
  with the projection effect is the honest effectively-once application
  boundary over at-least-once transport.
- Domain events, audit logs, and webhook events answer different questions and
  must not be replayed or reconstructed as substitutes for one another.
- A rebuildable projection needs generation, cutoff, freshness, coverage, and
  reconciliation evidence; otherwise a fast analytics table can present stale
  or partial data as product truth.
- Phase correctness and product correctness are different: chapter matrices
  prove that a slice was built safely, while the vision matrix proves that the
  slice advances the product THAAP intends to build.
- Deferring a scale mechanism can preserve the vision; leaving underwriting,
  drift, friendly-fraud, developer quality, or another user capability without
  exact ownership compromises it.
