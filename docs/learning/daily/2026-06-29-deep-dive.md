# Daily Deep Dive: 2026-06-29

This deep dive explains the final Chapter 19 review closure and the repository
process added to prevent the same review failures from recurring.

## 1. System Goal

- Make endpoint disable monotonic against every path that can create retryable
  work.
- Make merchant deduplication depend on authenticated event identity.
- Keep network authority and durable event time semantically stable across
  representation boundaries.
- Keep delivery-attempt evidence truthful when a worker crashes before HTTP,
  after dispatch begins, during a partial socket write, or after endpoint
  disable.
- Bound DNS resolution, HTTP status parsing, and legacy migration
  representations so infrastructure edges cannot masquerade as lease
  uncertainty.
- Replace memory-based “review harder” behavior with an executable
  plan-to-invariant-to-proof completion gate.

## 2. Plain-English Design Brief

- A review is complete only when every product promise has a named failure
  sequence, production enforcement point, and adversarial proof.
- A test suite built outward from code can prove the implementation it knows
  about while missing the promise the code failed to implement.
- For concurrency, “two threads ran” is not proof. The test must place each
  transaction at the dangerous boundary and demonstrate the relevant lock.
- For protocols, exact bytes, authenticated fields, URI authority, database
  precision, and reference clients are separate boundaries.
- For delivery execution, “HTTP might have happened” is a separate durable
  state from “HTTP definitely did not happen.” Payments systems should not
  invent either side of that truth after a crash.
- A migration proof must include every legacy representation that was legal
  before the new constraint, not only the rows the new model prefers.
- No new product capability was pulled in. Existing advanced webhook operations
  and distributed scaling remain in their named owner slices.

## 3. Code Map

- `WebhookDeliveryFinalizationService` acquires endpoint shared state before
  locking and mutating a claimed delivery.
- `WebhookDeliveryClaimService` evaluates endpoint eligibility in an `EXISTS`
  subquery so top-level `FOR UPDATE SKIP LOCKED` locks delivery rows only, and
  still selects expired `DELIVERING` rows after endpoint disable so they can be
  closed honestly.
- `WebhookDeliveryAttempt` now records a durable dispatch-start marker and
  tri-state `httpRequestSent` evidence.
- `WebhookDeliveryExecutor` signs and validates target state before marking the
  dispatch boundary, then prepares dispatch immediately before HTTP.
- `SocketWebhookHttpTransport` rejects response statuses outside `100..599`,
  consumes bounded informational responses, uses a total request deadline, and
  records partial-write ambiguity as unknown send evidence.
- `WebhookHostResolver` applies an application deadline and bounded resolver
  worker pool around platform DNS resolution.
- `WebhookEndpointRepository` exposes the tenant-scoped pessimistic shared lock.
- `WebhookEventEnvelopeFactory` canonicalizes event time before serialization.
- `SocketWebhookHttpTransport` formats Host from URI authority, independently
  of the approved resolved address.
- `webhook-callback-fixture.py` verifies MAC, parses signed body identity, and
  rejects header disagreement.
- `WebhookDeliveryPostgreSqlConcurrencyTests` forces and proves the dangerous
  finalization/disable interleaving and the disabled expired in-flight recovery
  path on PostgreSQL.
- `CHAPTER_19_INVARIANT_PROOF_MATRIX.md` records 13 traced invariants.
- `invariant-proof-check.py` makes incomplete matrices commit-blocking.

## 4. Request/Data Flow

1. A claimed HTTP attempt fails retryably.
2. Finalization opens a new transaction and takes a tenant/endpoint shared lock.
3. It then locks the delivery and validates token plus attempt identity.
4. Disable must wait for the endpoint write lock; finalization either commits
   its retry first and disable exhausts it, or observes disabled state and
   exhausts directly.
5. No ordering leaves `RETRY_SCHEDULED` work behind a disabled endpoint.
6. Independently, the receiver verifies HMAC over timestamp and raw body,
   validates the signed body `id`, requires header equality, and records that
   authenticated ID transactionally with merchant side effects.
7. Separately, a worker crosses the durable dispatch boundary only after secret
   loading, signing, and target policy pass; lease recovery uses that marker to
   decide whether the expired attempt is known no-send or outcome-unknown.

## 5. Database Invariants

- Disabled endpoints have no pending or retry-scheduled claimable delivery.
- Retry finalization and disable share one endpoint serialization boundary.
- Payload `createdAt`, `occurred_at`, event `created_at`, and delivery creation
  begin from the same microsecond-precision instant.
- A legacy V8 `PENDING` delivery with `next_attempt_at` is translated to
  `RETRY_SCHEDULED` before V9 installs retry-time constraints.
- Attempt-table constraints permit null send evidence only for post-dispatch
  in-progress or outcome-unknown states; completed known outcomes must carry
  explicit true/false evidence.
- Composite tenant/event foreign keys and immutable payload hashes continue to
  enforce event/delivery lineage.

## 6. Security And Privacy Invariants

- HMAC secret behavior is unchanged: raw key is reveal-once and encrypted;
  prefix/hash remain safe metadata.
- `THAAP-Event-Id` is not treated as authenticated merely because it travels
  beside a signature. Signed body identity is authoritative.
- Payloads, URLs, signatures, raw error bodies, PII, PAN, CVV, card
  fingerprints, and idempotency material remain absent from logs/metrics.
- Host formatting preserves virtual-host and TLS identity without performing a
  second unchecked DNS resolution.

## 7. Fraud/ML Relevance

- Authenticated stable identity is necessary when webhook events later trigger
  review actions, labels, case updates, chargeback operations, or rule feedback.
- The matrix requires a data/ML lineage review even in infrastructure chapters,
  preventing generic callback enrichment from leaking mutable model/rule state.
- Rich fraud payloads remain excluded until their versioned lineage and privacy
  contract exists.

## 8. Tests As Proof

- `concurrentRetryFinalizationAndDisableCannotLeaveRetryScheduled` holds the
  delivery row, makes finalization acquire the endpoint share lock, proves that
  lock using PostgreSQL `FOR UPDATE NOWAIT`, then starts disable and releases
  the exact dangerous schedule.
- Fixture tests prove a valid signed body cannot be filed under a changed
  advisory event header.
- Host tests cross a domain URI with an IPv6 selected address and separately
  verify an IPv6 literal.
- Timestamp tests start with nanoseconds and prove one microsecond canonical
  value across payload and entity.
- Migration tests include immediate pending, scheduled pending, succeeded, and
  failed legacy webhook rows on H2 and PostgreSQL.
- Transport tests reject numeric `999`, consume `100 Continue` before final
  `204`, apply a total socket deadline, and bound non-returning DNS resolution.
- Lease tests distinguish pre-dispatch failure, post-dispatch unknown, partial
  write unknown, fifth-attempt exhaustion, and disabled expired in-flight
  recovery.
- Full contract tests still prove retry, lease recovery, target policy,
  payment/ledger independence, tenant isolation, and safe operations.

## 9. Staff Engineer Review Notes

- The lock-order fix adds endpoint-lock duration to retry finalization, but the
  transaction is short and avoids false kill-switch truth.
- The matrix adds ceremony only for non-trivial slices and uses a small
  machine-checkable format.
- The process does not claim tests prove all possible code behavior. It requires
  explicit proof for frozen product promises and hostile sequences.
- Broad infrastructure or a second webhook signature scheme would overbuild the
  correction; authenticated body identity plus agreement checking is enough.

## 13. Interview Narrative

Practice saying this out loud:

- The tradeoff I made was a short shared endpoint lock during retry
  finalization in exchange for a monotonic operational kill switch.
- The invariant I enforced was that a disabled endpoint has no claimable retry,
  regardless of finalization ordering.
- The production risk I reduced was false operational truth, unauthenticated
  merchant deduplication, protocol authority corruption, and payload/storage
  lineage drift.
- I deferred no newly discovered Chapter 19 debt; existing advanced operations
  retain their named future triggers.
- The tests prove the exact PostgreSQL interleaving, authenticated event
  identity, Host representation boundaries, timestamp canonicalization,
  migration normalization, status parsing, DNS deadline, and tri-state attempt
  evidence.
