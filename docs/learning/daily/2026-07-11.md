## 2. Payment Processing Concepts Learned

- Idempotency is bounded replay, not permanent identity. An expired creation
  key begins a new merchant credential epoch even when caller input and server
  pepper have not changed.
- At-least-once delivery means a stale claim snapshot should converge on
  current endpoint state without sending; terminal exhaustion would silently
  reduce delivery reliability.

## 3. Fraud Detection Concepts Learned

- Stable PAN/customer correlation remains separate from replay identity. The
  merchant lifecycle-epoch fix changes only credential derivation and does not
  split fraud velocity or ML entity lineage.

## 4. Security Concepts Learned

- Authorization is not durable permission: a cryptographic generation can
  change after a check and before exact use unless the lock/timestamp/signature
  boundary is atomic.
- Startup must inventory encrypted state for every reachable capability.
  Disabling a delivery worker does not disable endpoint replay or rotation APIs.

## 5. Architecture / Design Notes

- Deterministic replay needs a durable lifecycle epoch so replay is stable but
  post-expiry reuse creates a distinct credential.
- Failure types must encode recovery semantics; stale generation is not the
  same as tampered ciphertext or missing permanent key material.
- Fenced leases require lock-before-side-effect ordering. Ownership checked
  after mutation cannot protect an external or irreversible action.
- Phase 3 keeps PaymentAttempt as the unit of decision lineage. Features,
  decision, rule evidence, optional review intake, and optional processor truth
  all commit through the existing confirm transaction.
- The first rules score is a deterministic severity projection, not a fraud
  probability. This prevents an explainable simulator score from being
  misrepresented as calibrated ML output.
- Phase 3 persists non-matching rules as evidence. Missing execution and an
  executed non-match are operationally and analytically different facts.
