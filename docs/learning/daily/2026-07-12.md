## 2. Payment Processing Concepts Learned

- A local database flush is the last reversible validation boundary before an
  external authorization. Forcing a real constraint failure there proves the
  processor cannot observe incomplete fraud evidence.
- Idempotency recovery must delete the failed reservation after transaction
  rollback so the identical request can make one coherent retry.

## 3. Fraud Detection Concepts Learned

- A FeatureSnapshot is defensible only when the fraud engine can inspect no
  value outside that snapshot. Equal-looking reconstructed requests are a
  second source of truth.
- Feature type has two meanings that must agree: which typed column is
  populated and which type the immutable definition declares.

## 4. Security Concepts Learned

- Removing BIN, last4, IDs, metadata, and credentials from storage is
  insufficient if they remain available to the decision engine. The safe
  allowlist must constrain evaluation as well as persistence and APIs.

## 5. Architecture / Design Notes

- `DecisionFeatureContext` contains exactly the seven typed V1 features and is
  the sole `ConfirmDecisionEngine` input.
- `MaterializedFeatureSet` rejects any context/FeatureValue disagreement.
- V18 binds definition ID, code, version, and value type in one composite
  foreign key.
