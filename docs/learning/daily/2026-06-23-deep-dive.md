# Daily Deep Dive: 2026-06-23

This note is for end-to-end understanding of a Staff-level implementation slice.
It should make the code explainable, not merely documented.

## 1. System Goal

- We built a weekly public technical concept blog system.
- This matters because the founder wants to publish serious educational essays
  on payment-risk concepts without turning them into product updates or repo
  walkthroughs.
- The future capability is repeatable technical communication: every week can
  produce a credible public essay about payment correctness, fraud systems,
  security boundaries, ML lifecycle, operations, and product tradeoffs.

## 2. Plain-English Design Brief

- Simplest mental model: each post teaches one public concept in depth.
- Without this design, weekly writing would either become a changelog or drift
  toward generic fraud-platform commentary instead of proof-backed engineering
  narrative.
- We chose to build Markdown docs, a post template, a checklist, a topic
  backlog, a seed draft, and a scaffold script.
- We intentionally deferred website publishing, feeds, styling, analytics, and
  image generation because the first bottleneck is repeatable technical
  substance.

## 3. Code Map

- `docs/blog/README.md` defines the workflow and publishing rule.
- `docs/blog/POST_TEMPLATE.md` defines the Staff-engineer post shape.
- `docs/blog/WEEKLY_BLOG_CHECKLIST.md` defines the quality gate before moving a
  draft to `published/`.
- `docs/blog/TOPIC_BACKLOG.md` keeps topic selection focused on public
  payment-risk concepts.
- `docs/blog/drafts/2026-W25-why-fraud-systems-need-explainable-intelligence.md`
  is a seed public concept draft.
- `scripts/blog-week-start.sh` scaffolds future drafts.
- `docs/README.md` links the new system from the docs index.

## 4. Request/Data Flow

Describe the flow step by step:

1. The founder picks one public payment-risk concept for the week.
2. `scripts/blog-week-start.sh YYYY-WNN short-slug` creates a draft from the
   template.
3. The draft explains the concept from first principles.
4. The draft adds architecture diagrams, invariants, failure modes, security
   implications, operational signals, tradeoffs, and review questions.
5. The checklist gates publishing so the post stays public and concept-led.
6. `scripts/blog-public-check.sh` scans drafts for private project/status
   language before publishing.

## 5. Database Invariants

- No database schema changed.
- The equivalent documentation invariant is that public posts must not mention
  private product names, repository files, branches, commits, or weekly build
  status.
- If that invariant disappears, the post becomes a product update instead of a
  public concept essay.

## 6. Security And Privacy Invariants

- No secrets or payment data were introduced.
- The post template requires explicit security and privacy reasoning for posts
  that mention card data, tenant boundaries, credentials, audit logs, or
  investigator workflows.
- The protected principle is public safety and accuracy: teach privacy and
  security concepts without exposing private implementation context.

## 7. Fraud/ML Relevance

- The backlog prioritizes topics around explainable fraud decisions, real-time
  risk scoring, audit replay, rules versus ML, and agentic investigator support.
- It also marks public concepts that deserve future posts, such as real-time
  scoring, rule engines, model boundaries, agent workflows, event-driven risk
  processing, and feedback loops.

## 8. Tests As Proof

- This slice has shell-script and documentation verification rather than
  application tests.
- `scripts/blog-week-start.sh` should prove draft scaffolding and input
  validation.
- `scripts/blog-public-check.sh` should prove public drafts do not contain
  blocked private product or repo-status language.
- `scripts/learning-day-check.sh --deep-dive-required` should prove the
  learning trail remains complete.

## 9. Staff Engineer Review Notes

- Tradeoff: use a repo-native Markdown process instead of building a full blog
  app or publication pipeline.
- Risk reduced: weekly writing now has a repeatable public concept shape.
- Reversible: the drafts can later be exported to a website, LinkedIn, Medium,
  or another publishing target.
- Dangerous to overbuild now: CMS integration, theme work, analytics, or
  automation before the post quality loop is proven.
