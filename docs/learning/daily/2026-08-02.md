## 2. Payment Processing Concepts Learned

- A version resolver is part of the payment command boundary: malformed,
  unsupported, or retired API-version input must fail before processor or
  payment mutation, and tests must prove source non-interference.
- An investigation read can summarize payment and ledger state, but it cannot
  become a new payment authority or authorize a later mutation.

## 3. Fraud Detection Concepts Learned

- A complete explanation includes non-matched and unavailable controls, exact
  decision-time versions, precedence, score units, and explicit model absence.
  Rerunning today's rules would answer a different historical question.
- Projection data is useful for search and aggregates; source decision,
  review, label, dispute, and money rows retain action authority.

## 4. Security Concepts Learned

- Tenant qualification must cover every child join and browser cache key, not
  only the seed PaymentIntent lookup.
- OpenAPI is a disclosure boundary. Route grouping, schemas, descriptions,
  examples, errors, and generated reports all require prohibited-data tests.
- Exact-customer pivots use the existing merchant-qualified foreign key;
  HMAC anchors are reserved for already-pseudonymized correlation families.
