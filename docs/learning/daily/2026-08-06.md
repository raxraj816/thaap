## Three things worth remembering

### 1. A gate that has never run is not evidence — it is usually red

The Chapter 58 matrix recorded `C58-GEN-001` honestly: byte-stability was
"asserted by the script but not yet demonstrated by a recorded run." That phrasing
is easy to read as *nearly done*. It is not. The first execution of
`scripts/python-sdk-regeneration-check.sh` failed immediately.

The committed client carried contract digest `8ca1ba94…` while the committed
contract hashed to `97c0d31e…`. The SDK had been generated from a contract
predating the Chapter 53–56 endpoints. The same pattern then repeated:
`scripts/openapi-contract-check.sh` had never been wired into
`commit-readiness-check.sh`, and it too was red.

Two of three findings that day had the identical root cause. The correction is
now mechanical rather than cultural: both gates are invoked by the readiness
script, and `commit_readiness_check_tests.py` fails if either is removed.

### 2. The dangerous bug is the one where nothing fails

The stale SDK's most interesting consequence was not a missing model class. The
contract had stopped declaring `scenarioRunner` as a security scheme the client
could inject, so `Credentials(scenario_runner_token=…)` was accepted and the
header was simply never sent.

Nothing raised. Nothing 500'd. The server saw a merchant request with no runner
token, so `MerchantContextArgumentResolver` returned `TrafficOrigin.MERCHANT_API`
instead of `SYNTHETIC_SCENARIO` — and every payment the sandbox quickstart
generated would have been recorded as **live merchant traffic**, entering
live-only fraud metrics. A developer following the published quickstart would
have been quietly poisoning the merchant's own analytics.

The class of bug worth hunting is not the one that throws. It is the one where a
credential, a qualifier, or a flag goes missing and the system carries on
producing plausible, wrong data.

### 3. `raise … from None` does not delete the exception chain

`_SafeApiClient` translated generated transport exceptions into a safe typed
error with `raise ThaapApiError(...) from None`. Every secret-hygiene test passed:
no credential in `str(error)`, none in `repr(error)`, `__cause__` is `None`.

`__context__` was still there, referencing the generated `ApiException` whose
`body` holds the raw server response and whose `headers` hold the request headers.
`from None` sets `__suppress_context__`, which is a *rendering hint* for the
default traceback printer. Anything that walks the chain deliberately — Sentry,
structured log handlers, most error reporters — reads straight past it.

The fix is small: build the safe error inside the `except` block, raise it after
the block ends, so no exception is being handled at the raise point. The lesson is
larger. A non-disclosure claim about an exception has to be proven over the whole
reachable object graph — `str`, `repr`, `__cause__`, `__context__`, and every
attribute a reporter would serialise — not over what Python chooses to print.

## What I got wrong

I read `DeveloperScenarioController` and concluded that three of six scenario
operations required the runner token, because three call `requireScenarioRunner`
in the controller. I changed the contract, the check and the tests to encode that
split, and it was wrong: `DeveloperScenarioService.requireSynthetic` guards *all
six* service methods. The original blanket rule in the contract check was right
and I had "corrected" it toward a subtler error.

The tell was available and I skipped it — an existing test,
`trustedCredentialCreatesDeterministicTenantRunAndOrdinaryMerchantCannotCreateOne`,
asserts `POST /developer/scenario-runs` returns 403 for an ordinary merchant.
Reading one layer and generalising is how the original defect happened; I
reproduced it before catching it.

The durable fix is not "read more carefully." It is `@RequiresScenarioRunner` on
the handlers, with both the contract generator and
`OpenApiSecurityContractTests` deriving from that annotation. The declaration now
lives at the enforcement point, so neither can generalise over a path prefix
again.
