## 2. What Changed Architecturally

- Retry finalization and endpoint disable now share an explicit
  endpoint-before-delivery lock order.
- Authenticated payload event identity is the merchant deduplication authority;
  the event header must agree but is not independently trusted.
- Webhook event time is canonicalized before payload and persistence creation.
- Delivery attempt evidence now separates known no-send, known request-write,
  and genuinely unknown post-dispatch truth.
- Endpoint disable now stops any claimed delivery that has not yet persisted
  `dispatch_started_at`; claimed is not treated as already sent.
- Resolver deadline/capacity failures now use retryable no-send attempt
  evidence instead of terminal unsafe-target classification.
- Webhook encryption-key parsing now rejects the known-bad all-zero 256-bit key.
- Signed webhook payload construction now uses JSON serialization in both
  runtime and migration paths before hashing/signing exact merchant-verifiable
  bytes.
- Runtime signed-payload creation now uses an explicit Java-time mapper
  configuration and rejects payloads larger than 64 KiB measured as UTF-8
  bytes before hashing or persistence.
- Local/test HTTP is documented as loopback-only simulator behavior; non-local
  merchant delivery remains HTTPS plus explicit allowlist.
- `TD-0003` now owns old/new signing-secret rotation windows before shared
  non-local merchant webhook operations.
- `TD-0004` now owns shared-environment webhook delivery fairness/rate controls,
  and `TD-0005` owns endpoint creation idempotency before public/shared merchant
  onboarding.
- Webhook routing now names its existing-transaction precondition explicitly
  and has negative proof that standalone routing persists no event or delivery.
- V9 now documents and tests one conservative synthetic event for each legacy
  delivery because V8 stored no authoritative fan-out identity.
- Webhook metrics now separate bounded error causes across normal finalization,
  lease recovery, dispatch preparation, and bulk endpoint disable without
  tenant or endpoint tags.
- The socket response parser now accepts only exact HTTP/1.0 or HTTP/1.1 text
  status grammar; malformed version tokens remain transport failures.
- V9 rejects aggregate legacy execution claims without attempts and terminalizes
  pristine work for inactive endpoints.
- Signatures are minted after dispatch preparation; 64 KiB request and
  cumulative 32 KiB response-head limits are enforced at runtime boundaries.
- Bulk-disable metrics use actual per-event-type affected-row counts.
- Expired in-flight deliveries remain recovery-eligible even after endpoint
  disable, so the attempt closes as unknown and the delivery exhausts instead
  of becoming invisible.
- Non-trivial chapter completion now requires a machine-checked invariant-proof
  matrix and two distinct review passes.
- Completion now also requires honest matrix provenance, a severity-aware
  escaped-review register, a closure dossier, and custom-infrastructure ADR
  evidence. Chapter 19 remains visibly marked as retroactive recovery.

## 3. Risks That Decreased

- Disable can no longer race a waiting retry finalizer and leave claimable work.
- Merchant reference code no longer teaches deduplication on an unsigned field.
- DNS choosing IPv6 no longer corrupts a domain Host header.
- Immutable payload time no longer disagrees with microsecond database lineage.
- Unsupported legacy scheduled/succeeded/failed representations now fail V9
  before incomplete attempt history can be created.
- Out-of-range numeric HTTP statuses no longer roll back finalization and get
  misclassified as lease uncertainty.
- DNS resolution and partial socket writes are bounded and represented
  honestly.
- Unknown host, empty DNS answers, and unexpected resolver failures no longer
  become permanent target denial.
- A final `2xx` status line cannot become success until its bounded HTTP
  response head is structurally complete.
- A merchant kill switch can no longer lose to a worker that claimed a row but
  had not reached the durable dispatch boundary.
- Local DNS resolver saturation no longer permanently exhausts an otherwise
  valid endpoint as `TARGET_NOT_ALLOWED`.
- A predictable all-zero key can no longer encrypt merchant webhook signing
  secrets.
- Manual string concatenation can no longer malform signed webhook payloads
  if event/resource values evolve.
- A future bare caller can no longer overlook the webhook routing transaction
  precondition during code review, and removal of mandatory propagation would
  fail the negative contract test.
- Legacy delivery rows cannot be silently grouped into fabricated sibling
  event lineage during V9 migration.
- Classpath-wide Jackson module discovery no longer controls the production
  mapper bean, and future oversized webhook payloads fail closed before they
  become signed delivery state.
- Test-count confidence is replaced by frozen-plan traceability and hostile
  failure-sequence proof.
- Distinct webhook failures no longer collapse into one operational series.
- A malformed `HTTP/not-http 204` response can no longer become successful
  merchant acknowledgement truth.
- Twelve escaped Chapter 19 findings are now classified under immutable
  `ER-NNNN` IDs. Repeated weak-proof and missing-failure-sequence categories
  changed the repository process and executable gates.

## 6. Design Review Narrative

- The key correction is methodological: derive tests from frozen invariants and
  failure sequences, not only from implemented classes.
- Concurrency proof requires controlled ordering and durable postconditions.
- Protocol proof includes docs and fixtures because merchant behavior is part
  of the product's security boundary.
- Chapter completion is now a repository-verifiable claim rather than a chat
  conclusion.
- The uncomfortable lesson is that “I fixed many issues” is not evidence. The
  only defensible evidence is a frozen invariant, a named failure sequence, and
  a test or executable gate that would fail if the old bug returned.
- The specific disable lesson is that operational controls need a precise
  boundary. In THAAP that boundary is `dispatch_started_at`, not claim
  ownership.
