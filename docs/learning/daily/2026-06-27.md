# Daily Learning Note: 2026-06-27

## 1. What We Built

- Hardened Chapter 16 after an end-to-end Senior Staff review.
- Made the generator fail on unexpected ledger, authorization, amount, network,
  3DS, FraudDecision, or FeatureSnapshot truth.
- Restricted generation to loopback targets and moved the admin token from
  command arguments to `THAAP_ADMIN_BOOTSTRAP_TOKEN`.
- Added collision-resistant run IDs, local lineage metadata, atomic summary
  writes, valid deterministic E.164 phone data, and a processor-neutral
  authorization response.

## 2. Payment Processing Concepts Learned

- A verification artifact is trustworthy only when invariant violations make
  the run fail. Reporting false ledger truth as a boolean is weaker than
  rejecting the run.
- Requested amount, authorized amount, authorization status, and network status
  are separate claims and should be verified independently.

## 3. Fraud Detection Concepts Learned

- A scenario is not fraud lineage merely because it has a decision ID. The
  decision and feature snapshot must both point to the same PaymentAttempt.
- Local `syntheticRunId` metadata supports debugging, but it is not a trusted
  training-data classification because merchants control PaymentIntent
  metadata.

## 4. Security Concepts Learned

- Secrets passed as command arguments may be visible through process inspection
  or command tracing. Environment lookup avoids that exposure path.
- A local-only generator needs an enforced loopback boundary, not only
  documentation saying it is local.

## 5. Architecture / Design Notes

- Merchant-facing authorization evidence now returns processor-neutral fields;
  the internal simulator outcome remains durable but is not a public contract.
- Run identity is unique even for concurrent same-seed runs, is attached to
  generated PaymentIntents, and names an atomic summary artifact.
- Authoritative synthetic-origin classification is intentionally not inferred
  from merchant metadata.

## 7. Bugs, Surprises, Or Tradeoffs

- The prior phone suffix used hexadecimal characters, producing values such as
  `+1555016c49`; decimal derivation now creates valid `+1` E.164-shaped values.
- Timestamp-only run IDs could collide within one second. The run ID now combines
  microseconds, seed digest, and random entropy.
- Atomic output prevents partial summary files, but interrupted multi-request
  generation is not resumable yet. That debt belongs to the future generator
  reliability/volume slice before scheduled, high-volume, or automatically
  retried runs.

## 8. Open Questions

- What trusted schema should eventually distinguish synthetic, test-mode, and
  live traffic for analytics and ML dataset governance?
- What durable run-state and cleanup protocol should support safe resume without
  duplicating merchants, attempts, or fraud evidence?
