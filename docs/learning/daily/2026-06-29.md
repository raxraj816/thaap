## 2. Payment Processing Concepts Learned

- A webhook kill switch is part of payment operations even though it moves no
  money. Once disabled, it must be impossible for a stale failure path to
  recreate claimable work.
- Committed payment truth remains independent from callback delivery. The fixes
  change delivery convergence and merchant safety without rewriting the
  PaymentIntent or ledger.

## 3. Fraud Detection Concepts Learned

- Stable authenticated event identity matters for later fraud-review and label
  workflows: deduplicating on an unsigned header could suppress the wrong
  analyst or merchant side effect.
- The invariant matrix includes data/ML lineage so future fraud events cannot be
  declared complete from API happy paths while replay identity is ambiguous.

## 4. Security Concepts Learned

- The Chapter 19 HMAC covers timestamp plus raw body, not the event ID header.
  Therefore the merchant must verify the body first, parse `id` from that signed
  body, and only then require header agreement.
- A reference callback fixture is security product code. If it demonstrates an
  unsafe order, every merchant copying it inherits the defect.
- The HTTP Host authority comes from the original URI. DNS selecting an IPv6
  address does not turn a domain name into an IPv6 literal.

## 5. Architecture / Design Notes

- Global lock order for the kill-switch path is endpoint before delivery.
  Routing and retry finalization take endpoint shared locks; disable takes the
  endpoint write lock before bulk delivery exhaustion.
- Event time is canonicalized once to microseconds before payload serialization,
  hashing, event persistence, and delivery creation.
- Completion evidence is now traceable as
  `plan promise -> failure sequence -> production boundary -> adversarial test`.

## 7. Bugs, Surprises, Or Tradeoffs

- The previous concurrency coverage used simultaneous starts. That catches some
  races but does not prove the exact schedule where one transaction validates
  state, waits, and writes after a conflicting commit.
- Broad green-suite counts created false confidence because docs, fixtures, and
  representation edges were not traced independently to plan promises.
- The earlier approach still missed issues because the proof was reconstructed
  too late from the code and selected tests. The corrected approach freezes the
  failure sequence first, reopens the matrix before changing code, and only
  marks completion after a second hostile pass.
- The hostile lock-order pass found that a top-level PostgreSQL `FOR UPDATE`
  over a delivery/endpoint join can lock both tables. Claim selection now uses
  an endpoint `EXISTS` check so only the delivery is row-locked and the
  endpoint-first kill-switch protocol cannot inherit a hidden inverse lock.
- The corrective process is deliberately stricter for non-trivial chapters; the
  small artifact cost is justified by payment/security failure impact.
