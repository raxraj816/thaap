## Engineering lessons

- Compute-before-processor is not enough; the computed action must be applied
  to coherent payment state and flushed with its evidence.
- Append-only rows prevent rewriting history, while composite semantic foreign
  keys prevent creating internally contradictory history.
- H2 can validate fast contracts, but PostgreSQL must certify nullable query
  typing, migrations, composite keys, and lock ordering.
- Applied Flyway files are deployment history. Repairs belong in new migrations.
- Subscription migrations must preserve explicit customer selection rather
  than treating every existing endpoint as subscribed to future event types.
- A review outcome, payment action, and fraud label are distinct facts; merging
  them would create false training and audit truth.
- Redis cannot be transaction truth. Stable logical-attempt identity and
  conservative ambiguity handling make its bounded failure semantics explicit.
- Candidate authentication is not mutation authorization. Operator status and
  role are revalidated under lock before review state or label truth changes.
- A current assignment is a projection; append-only events plus a deferred
  PostgreSQL check make the projection explainable without depending on ORM
  flush order.

## Integrated closure lessons

- Chapter-local demos are executable product clients and must evolve when later
  chapters add always-materialized features or stronger request guards.
- When Redis is fully unavailable, the rate-limit boundary returns 503 before
  payment truth; this correctly outranks velocity's later REVIEW degradation.
- Durable suspected incidents must come from committed payment/control rows,
  never ephemeral abuse counters. Operator mitigation remains a recorded action,
  not an automatic policy mutation.
- Exact current/previous HMAC enforcement prevents a key rotation from briefly
  resetting limits; raw credentials, IPs, and idempotency keys never enter Redis.
